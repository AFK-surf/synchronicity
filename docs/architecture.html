synchronicity — an omnipresent
peer-to-peer file store

Every node publishes one signed Merkle-Patricia trie of its own file metadata and replicates every trusted peer's trie by anti-entropy. Metadata is everywhere; content is fetched on demand and verified byte-range by byte-range against its BLAKE3 root.

01 Inside one node

The CLI is a thin control-socket client; the daemon owns the node. Engine subsystems all read and write a single SQLite database and a filesystem CAS, and reach peers through one iroh endpoint.

02 The core mechanism — single-writer tries, two verified paths

This is the idea the whole system turns on. Metadata sync is conflict-free because each origin trie has exactly one writer; content moves on a separate path, verified independently. Follow the two colored routes.

03 What a trie holds

Each origin trie maps byte-string keys to postcard-encoded records. A single prefix byte namespaces the keyspace; because the Merkle-Patricia trie compresses shared prefixes, the f: namespace mirrors directory structure and a listing is a range scan.

KeyValueMeaning
f:<space>/<path>FileEntryThis origin's copy of a file — size, mtime, content root, chunking, lineage. Paths are NFC-normalized with no .. — enforced on ingest of a peer's trie, not just when writing our own.
b:<object root>BlobAd"I hold (part of) this object" — held byte spans coalesced to 16 MiB. This is how any node answers "who can serve range R of X?" locally, with no query round-trip.
m:selfNodeManifestNode info: name, advertised spaces, published version.

04 Trust & membership

Authorization is binary and membership-based, enforced on connection accept and re-checked per stream. Two sources feed one bindings table; a device key with no live binding is refused at the QUIC layer before it can read a single record.

06 Load-bearing properties

The guarantees the design leans on — each one is why some class of conflict or attack simply cannot arise.

Conflict-free by construction

Origin tries are single-writer: only the origin mutates its own trie. Replicating a peer is just "catch up to their latest signed root" — no merge, ever.

Three hash layers

Trie nodes verified against requested hashes; heads against origin signatures; content against object roots per 16 KiB group. A peer can withhold, never corrupt.

Availability is local

"Who can serve range R of X?" is answered by scanning synced b: ads — no DHT, no query round-trip. Swarm fetch falls out naturally.

Progress survives restarts

Verified groups are committed to the CAS and fsynced as they arrive; a re-issued fetch skips whatever is already held.

Fail closed

An unvalidated DNSSEC answer is discarded and the cached member set retained. A prolonged outage shrinks membership toward static-only — it never falls open.

Interpretation at the edge

The stored state is the union of per-origin tries. All conflict questions live in the derived unified tree (§8), where a path carries one version per distinct content root.
